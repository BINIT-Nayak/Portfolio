# SEO and sharing

The production origin is `https://binit-nayak.netlify.app`, matching README. `lib/seo.ts` owns this value and the page metadata builder. Update it when changing the production domain; canonicals, social URLs, structured data and sitemap entries share that source.

## Metadata and discovery

- Home, Projects, Case Studies and all 12 case studies have their own title and description, absolute canonical URL, Open Graph title/description/URL/type, and Twitter large-image card.
- Titles include Binit Nayak explicitly so homepage and nested-route title inheritance cannot produce inconsistent social/browser titles.
- Metadata uses Frontend/Full Stack Engineer, React, TypeScript, Java, Spring Boot and Hyderabad where relevant. No repeated keyword list or hidden SEO content was added.
- `/opengraph-image` is a generated 1200×630 PNG matching the portfolio’s dark visual language. All pages share the branded image but have distinct social titles/descriptions. The old portrait was not a verified 1200×630 share asset.
- `/icon.svg` provides the BN favicon; `/apple-icon` provides a 180×180 PNG touch icon. Next.js file metadata generates the icon links.
- `/robots.txt` permits public crawling and points to `/sitemap.xml`. The sitemap contains 15 distinct canonical page URLs: three listings/home plus 12 case-study destinations. It omits query strings, hash fragments and asset URLs. There are no invented last-modified dates, priorities or update frequencies.
- Dialog previews remain available, but every explorer card also has a normal crawlable “Read full case study” link. The dialog’s reading link also points to the canonical article.

## Structured data

`lib/structured-data.ts` supplies:

- A shared Person and WebSite graph with stable IDs, supported identity/profile links, Hyderabad location and relevant engineering subjects.
- ProfilePage on Home, pointing to the Person.
- A Projects ItemList containing three SoftwareApplication entities, using actual product descriptions, screenshots and concrete capabilities.
- A case-study ItemList on the explorer.
- CreativeWork and BreadcrumbList on every case-study page, including Comet.

`JsonLd` serializes these on the server and escapes `<` before embedding JSON. No ratings, testimonials, prices, offers, employment claims, precise publication dates or benchmark figures were invented. Schema validity does not guarantee a search-engine rich result or indexing.

## Verification

Validation passed for all 15 canonical pages, including the generated assets and unknown-slug response. Chrome checks of the eight new articles found no axe violations or mobile page overflow; the Toast article link and interactive demo also passed. Production build, TypeScript, lint and CSS checks passed.

Run a production build and local server, then:

```sh
node scripts/audit-seo.mjs
```

Set `AUDIT_URL` if the server is not at `http://127.0.0.1:4188`. The script fetches HTML without executing JavaScript and validates unique titles/descriptions, canonicals, social fields, one h1 per page, parsed JSON-LD, crawlable study links, sitemap/robots, actual PNG dimensions, favicon availability and unknown-slug 404 behavior.

After deployment, confirm the hosting platform serves these routes without an overriding redirect or robots header, and submit the sitemap through the site owner’s search-console account if desired. No deployment or external indexing submission is performed by this implementation.

Implementation references: [Next.js 14 metadata](https://nextjs.org/docs/14/app/building-your-application/optimizing/metadata), [SoftwareApplication](https://schema.org/SoftwareApplication), [CreativeWork](https://schema.org/CreativeWork).
